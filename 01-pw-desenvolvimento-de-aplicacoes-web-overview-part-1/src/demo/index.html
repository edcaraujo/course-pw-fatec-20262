01. Fundamentos Globais

Internet e World Wide Web (WWW)

A diferença fundamental entre a infraestrutura física/lógica e os serviços de hipertexto.

🌐 O que é a Internet?
A Infraestrutura Global de Transporte
  • Rede de Redes: Bilhões de dispositivos conectados (roteadores, switches, cabos submarinos de fibra e satélites).
  • Protocolo Base: Opera sob a suíte de protocolos TCP/IP.
  • Rodovia Digital: Suporta múltiplos serviços independentes:
    Web (HTTP) E-mail (SMTP) Arquivos (FTP) Streaming (RTSP/UDP)
📄 O que é a Web (World Wide Web)?
O Sistema de Informações e Hipertexto
  • Documentos Interligados: Baseia-se no conceito de Hipertexto (links acessíveis via navegadores).
  • A Tríade Fundamental:
    1. HTML: Estrutura e conteúdo da informação.
    2. HTTP / HTTPS: Protocolo de comunicação e transporte.
    3. URL / URI: Sistema de localização e endereçamento único global.
💡 Nota para o Professor: Destaque para a turma a analogia da rodovia (Internet) versus os carros que trafegam nela (Web, Email, Streaming). Muitos alunos confundem achar que a Internet é apenas o navegador.
02. História & Padrões

Origem da Web & Os Três Pilares

Como Tim Berners-Lee criou a base da tecnologia livre e royalty-free no CERN em 1989.

👨‍💻 O Criador & CERN

Sir Tim Berners-Lee propôs a Web em 1989 no laboratório do CERN (Suíça) para facilitar o compartilhamento de pesquisas entre cientistas.

Primeiro Site (1991):
https://info.cern.ch/
🔓 Royalty-Free

Lançada publicamente em 1991 como tecnologia Royalty-Free (gratuita e aberta), o que permitiu sua adoção e evolução exponencial por todo o planeta.

📐 Padronização W3C

Garante a interoperabilidade entre navegadores e sistemas operacionais mantendo padrões abertos para HTML, CSS e APIs.

06. Comunicação entre Serviços

APIs, API Gateway & Padronização de Interfaces

Tecnologias de integração: REST vs GraphQL vs gRPC e padrões BFF (Backend for Frontend).

📡 REST

Padrão baseado nos verbos HTTP (GET, POST, PUT, DELETE). Stateless e fácil de cachear.

⚡ GraphQL

Permite que o cliente solicite exatamente os campos necessários, evitando over-fetching e under-fetching.

🚀 gRPC

Comunicação binária de altíssima performance via HTTP/2 e Protocol Buffers (ideal para backend-to-backend).

08. Teoria de Sistemas Distribuidos

Teorema CAP & Consistência Eventual

O teorema de Eric Brewer: Em redes sujeitas a partição, é necessário escolher entre Consistência estrita (CP) ou Disponibilidade alta (AP).

📐 TRIÂNGULO CAP & SIMULADOR DE PARTIÇÃO DE REDE
C Consistência
A Disponibilidade
P Tolerância
Nó A (São Paulo)
⚡ Conexão OK
Nó B (Virgínia - EUA)
Estado Normal: Os dois nós trocam confirmações de escrita síncronas sem falhas na rede.
Consistência (Consistency)

O que significa? Todos os nós da rede leem exatamente a mesma informação atualizada no mesmo milissegundo. Se um valor é alterado no Nó A, o Nó B é bloqueado até sincronizar.

Trade-Off Arquitetural na Web: Como falhas na rede (Partições) são inevitáveis na Internet global, a maioria das aplicações Web sacrifica a Consistência Rígida em favor da Consistência Eventual (Eventual Consistency) para nunca deixar a página do usuário fora do ar (AP).
Extensão Teorema PACELC: Se houver Partição (P), escolha entre A ou C; Senão (E), escolha entre Latência (L) ou Consistência (C).
09. Persistência & Modelagem de Dados

Matriz de Seleção & Tipos de Bancos de Dados

Comparativo aprofundado dos 5 paradigmas de armazenamento: SQL vs Documentos vs Chave-Valor vs Wide-Column vs Grafos.

🗄️ Paradigmas de Armazenamento
💎 SQL (Relacional)

PostgreSQL, MySQL. ACID, Tabelas, Joins complexos. Ideal para: Finanças, ERP.

📄 Documento

MongoDB. JSON flexível, Coleções dinâmicas. Ideal para: Catálogo, CMS.

⚡ Chave-Valor

Redis, DynamoDB. RAM sub-ms, Estruturas em memória. Ideal para: Cache, Sessão.

📊 Wide-Column

Cassandra, Scylla. Gravação massiva distribuída. Ideal para: Logs, IoT.

🕸️ Grafos

Neo4j, Amazon Neptune. Nós e Arestas. Otimizado para conexões e recomendações em redes sociais.

10. Altas Cargas de Tráfego

Escalabilidade de Dados: Replicação, Sharding & Hashing

Como superar gargalos de banco de dados quando a aplicação escala horizontalmente.

🔄 Replicação Master-Slave

1 Nó de Escrita (Master) sincroniza assincronamente para N Nós de Leitura (Slaves). Aumenta dramaticamente a vazão de leitura.

🧩 Sharding (Horizontal)

Divide tabelas gigantescas em múltiplos servidores baseados em uma Shard Key (ex: ID do Usuário ou Região Geográfica).

⭕ Consistent Hashing

Algoritmo em anel distribuído que minimiza a reorganização de dados quando nós são adicionados ou removidos da rede.
